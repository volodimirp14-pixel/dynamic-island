## 2. Как устроено сейчас

### 2.1. Запуск через Windhawk
1. Windhawk загружает мод в свой процесс `windhawk.exe`.
2. Служебный блок в конце файла (`Wh_ModInit` / `Wh_ModAfterInit`) запускает **отдельную копию** `windhawk.exe -tool-mod <id>`.
3. В этой копии вызывается `WhTool_ModInit()` → `LoadSettings()` + `StartThreads()`, а «главная функция» процесса подменяется через `Wh_SetFunctionHook`, чтобы процесс не делал ничего своего.
4. Мьютекс `windhawk-tool-mod_<id>` не даёт запустить две копии.
5. Изменение настроек в Windhawk → `Wh_ModSettingsChanged` → `LoadSettings()`.
6. Выключение мода → `WhTool_ModUninit()` (останавливает потоки, возвращает баннеры Telegram/Discord) → `ExitProcess`.

### 2.3. Все зависимости от Windhawk
| Что | Сколько | Чем заменить |
|---|---|---|
| `Wh_GetIntSetting` / `Wh_GetStringSetting` / `Wh_FreeStringSetting` | 72 | Свой `SettingsStore`, читающий `settings.json` |
| Блок `==WindhawkModSettings==` (YAML) | 1 | Схема настроек (один файл-описание), из неё строятся и значения по умолчанию, и проверка, и страницы Launcher |
| `Wh_GetIntValue` / `Wh_SetIntValue` / `Wh_Get/SetStringValue` — мелкое состояние: `QuietMode`, `ManuallyHidden`, `PinnedExpanded`, `GameOverlayPinned`, `ExpandOnHoverOverride`, `PillOpacityOverride`, `NotchStyleOverride`, `TelegramBannerBackup`, `ProgressPercent` | 45 | Файл `state.json` (отдельно от настроек) |
| `Wh_Log` | 87 | Свой лог-файл с ротацией + `OutputDebugString` |
| `Wh_ModInit`, `Wh_ModAfterInit`, `Wh_ModSettingsChanged`, `Wh_ModUninit`, `Wh_SetFunctionHook`, мьютекс tool-mod | 1 блок | Обычная функция `wWinMain`, свой мьютекс одного экземпляра, команды от Launcher |
| `WH_MOD_ID`, `@compilerOptions` (список библиотек) | — | CMake-проект, те же библиотеки |
| Пункт меню «Open Windhawk settings» (ищет `windhawk.exe`) | 1 | «Открыть Launcher» |
| `GameDetector` считает окна Windhawk «не игрой» (`windhawk.exe`) | 1 | Заменить на свой Launcher |

**Скрытые зависимости, которые легко пропустить:**
1. **Масштаб экрана (DPI).** Сейчас программа получает правильный режим DPI от `windhawk.exe`. Своему `.exe` нужен манифест с `PerMonitorV2`, иначе остров будет размытым и сдвинутым на экранах 125–200 %.
2. **Доступ к уведомлениям.** Windows разрешила его `windhawk.exe` (статус 1 в вашем логе). Для нашего `.exe` это та же общая настройка «Разрешить приложениям доступ к уведомлениям», но проверить нужно в самом начале (п. 7, этап 2a).
3. **Компилятор.** Windhawk собирает мод своим clang (llvm-mingw) со своими заголовками WinRT. Нам нужен свой компилятор с заголовками C++/WinRT (их даёт Windows SDK).
4. **Баннеры Telegram/Discord.** При выключении мода сейчас возвращается `ShowBanner`. В автономной версии это должно происходить при выходе из программы **и при удалении** (деинсталлятор должен вызвать возврат), иначе после удаления Telegram останется без баннеров.
5. **Две копии сразу.** Если включены и мод Windhawk, и новая программа — будет два острова и они будут спорить за `ShowBanner`. Новая программа должна видеть мьютекс мода Windhawk и предупреждать.

## 4. Предлагаемая архитектура

### 4.1. Два процесса, не больше
```
DynamicIsland.exe            — сам остров (ядро + интерфейс), работает в фоне
DynamicIslandLauncher.exe    — окно управления; открывается и закрывается когда угодно
```
Третий процесс (служба, отдельный «апдейтер», трей-агент) не нужен: обновления проверяет Launcher, автозапуск делает Windows.

Почему ядро и интерфейс острова — **один** процесс: сейчас они так и работают, обмениваются данными в памяти; разделение дало бы только задержки и сложность.

### 4.2. Модули внутри `DynamicIsland.exe`
Сейчас всё в одном файле. Делю на файлы **без изменения поведения** (сначала механически, потом проверка):
```
src/island/
  app/            wWinMain, один экземпляр, запуск/остановка потоков, команды от Launcher
  settings/       схема, settings.json, state.json, проверка и восстановление
  log/            лог-файл
  platform/       DPI, мониторы, DWM-размытие, горячие клавиши, автозапуск
  ui/             Renderer, анимации, раскладки, вкладки, Liquid Glass, меню
  sources/        медиа, звук, яркость, Bluetooth, батарея, погода, акции, железо
  notifications/  слушатель, Telegram, Discord, баннеры, ToastWatcher
  game/           GameDetector, игровой режим, «Не беспокоить»
src/shared/       схема настроек, протокол команд, версия — общие для обоих exe
src/launcher/     Launcher
installer/        скрипт установщика
```

### 4.3. Связь Launcher ↔ остров (простой и надёжный вариант)
Named Pipes и сервер не нужны. Хватает трёх штатных механизмов Windows:

| Задача | Механизм |
|---|---|
| Только один остров | Именованный мьютекс `Local\DynamicIsland.Instance` |
| «Остров запущен?» | Launcher ищет скрытое служебное окно острова (`DynamicIsland.Control`) |
| Команды: «перечитай настройки», «выйти», «перезапуск», «показать» | `WM_COPYDATA` в это служебное окно (короткая строка-команда) |
| Передача настроек | Launcher пишет `settings.json` **атомарно** (во временный файл → замена), потом шлёт «перечитай» |
| Страховка | Остров следит за изменением `settings.json` (`ReadDirectoryChangesW`), так что изменения подхватятся, даже если команда потерялась |

Повторный запуск `DynamicIsland.exe` (например, двойной клик по ярлыку) → новая копия видит мьютекс, говорит работающей «показаться» и сразу закрывается.

### 4.4. Настройки
- **Где:** `%APPDATA%\DynamicIsland\settings.json` — ваши настройки; `%APPDATA%\DynamicIsland\state.json` — служебное состояние («Не беспокоить», скрыт/закреплён, бэкап баннеров); `%LOCALAPPDATA%\DynamicIsland\logs\` — логи. Не временные папки и не папка программы, поэтому обновление и переустановка их не трогают.
- **Формат:** JSON с полем `schemaVersion`. Ключи — те же, что сейчас (`Telegram.Enabled`, `Themes.BackdropMaterial`…), чтобы не путаться.
- **Одна схема на всё:** каждый параметр описан один раз (тип, значение по умолчанию, min/max, варианты, название и подсказка по-русски). Из схемы: значения по умолчанию, проверка, и страницы Launcher строятся автоматически — новый параметр добавляется в одном месте.
- **Защита:** неизвестные ключи игнорируются; значение вне диапазона → поджимается; неверный тип → значение по умолчанию (с записью в лог); испорченный файл → переименовывается в `settings.broken-<дата>.json`, берутся значения по умолчанию, Launcher показывает предупреждение. Перед каждой записью хранится `settings.json.bak`.
- **Миграции:** при росте `schemaVersion` старые ключи переводятся в новые кодом миграции.
- **Перенос из Windhawk:** при первом запуске попробовать прочитать текущие настройки мода из хранилища Windhawk (где именно они лежат у вас — проверю на этапе 2; если не выйдет — Launcher предложит перенести вручную, по умолчанию стоят те же значения).

### 4.5. Launcher — рекомендую WebView2
Окно Launcher — небольшая программа на C++ (тот же компилятор и проект), внутри которой страница HTML/CSS (движок **WebView2** — это Edge, он уже встроен в Windows 10/11).

| Вариант | Плюсы | Минусы |
|---|---|---|
| **C++ + WebView2 (рекомендую)** | Современный вид легко (Fluent-стиль, тёмная тема, анимации); маленький `.exe` (~1–2 МБ); тот же проект и компилятор; страницы настроек строятся из схемы; HTML-макет могу показывать вам на картинках ещё до сборки | Нужен WebView2 Runtime — есть в Windows 11 и обновлённой Windows 10; установщик поставит, если нет |
| WPF (.NET 8) + библиотека Fluent | Быстро писать | Нужен .NET Runtime (или +70–150 МБ к установщику); второй язык (C#) в проекте |
| WinUI 3 | «Родной» вид Windows 11 | Тяжёлая сборка и развёртывание (Windows App Runtime), сложнее без MSIX |
| Чистый Win32 / свой Direct2D | Никаких зависимостей | Огромный объём ручной работы ради 109 настроек |

**Разделы Launcher** (по вашему ТЗ): Главная (запуск/остановка/перезапуск, состояние, версия, быстрые переключатели) · Внешний вид · Анимации · Поведение и положение · Модули (погода, акции, железо…) · Уведомления (Telegram, Discord, длительность…) · Игры · Система (автозапуск, производительность) · Обновления · О программе (версия, логи, сброс настроек).

### 4.6. Автозапуск и фон
- Автозапуск: запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (без прав администратора; видна и отключаема в Диспетчере задач → «Автозагрузка»). Переключатель в Launcher и галочка в установщике.
- Остров стартует сам по себе, Launcher ему не нужен.
- Корректное завершение: команда «выйти» → остановка потоков → возврат баннеров → выход. Если процесс завис (не ответил за 5 с) — Launcher предложит завершить его принудительно.

### 4.7. Установщик, удаление, обновления
- **Установщик:** Inno Setup (бесплатный, простой, проверенный). Установка **для текущего пользователя** в `%LOCALAPPDATA%\Programs\DynamicIsland` — без запроса прав администратора, и обновления потом тоже без UAC. Ярлыки в меню «Пуск» (и на рабочем столе по галочке), галочка «Запускать вместе с Windows», проверка/установка WebView2.
- **Удаление:** закрывает остров, возвращает баннеры Telegram/Discord, убирает автозапуск. Вопрос «Удалить также настройки?» — по умолчанию **нет**.
- **Обновления:** релизы на GitHub. Launcher (по кнопке и, по желанию, раз в день) смотрит последний релиз, сравнивает версию, скачивает установщик, **проверяет контрольную сумму SHA-256**, закрывает остров и запускает установку в тихом режиме; настройки не трогаются. Отправляется только запрос к GitHub, никаких личных данных.
- **Подпись кода:** без платного сертификата Windows SmartScreen будет показывать «Неизвестный издатель» при первой установке. Это не ошибка, но нужно нажать «Подробнее → Выполнить в любом случае». Сертификат можно купить позже.

### 4.8. Сборка
- CMake + компилятор Microsoft Visual C++ (Visual Studio 2022 Build Tools, бесплатно) + Windows SDK (в нём заголовки C++/WinRT) + WebView2 SDK.
- Код писался под clang Windhawk; под MSVC возможны мелкие правки компиляции — это ожидаемо и делается один раз.
- **Важно про проверку:** в моей среде нет Windows и заголовков WinRT. Варианты:
  1. **GitHub + GitHub Actions (рекомендую).** Репозиторий на вашем GitHub, сборка идёт на серверах GitHub под Windows автоматически при каждом изменении. Я вижу ошибки компиляции сам и исправляю их до того, как файл попадёт к вам. Готовый установщик скачивается из раздела Releases. От вас: аккаунт GitHub и подключение репозитория к сессии.
  2. **Сборка у вас.** Ставите Visual Studio Build Tools (~5–8 ГБ), запускаете `build.bat`, присылаете ошибки, если будут. Медленнее, больше ручной работы.
- Git: с этого этапа история ведётся в репозитории (см. п. 8).

## 5. Производительность
Новых постоянных нагрузок нет — переносится тот же код:
- Цикл кадров уже «паркуется» (0 % CPU) при скрытии; без анимации кадры не рисуются.
- Опросы: игры раз в 0,5 с (1,5 с в «парковке»), уведомления раз в 1 с, погода раз в 15 мин, акции только пока вкладку смотрели.
- Launcher закрыт большую часть времени → 0 ресурсов. Открытый — ~60–100 МБ (WebView2), закрывается без следа.
- Остров без Windhawk даже немного легче: не загружается движок Windhawk.
- Добавляю защиту: лог с ограничением размера (5 МБ × 3 файла).

## 6. Риски и как их снимаю
| Риск | Вероятность | Что делаю |
|---|---|---|
| Windows не даст `.exe` доступ к уведомлениям | Низкая (windhawk.exe — тоже обычная программа без пакета, и доступ у него есть) | Проверяю **первым делом** маленькой тестовой сборкой. Запасной путь для Telegram (чтение баннера через UI Automation) работает и без доступа |
| Ошибки компиляции под MSVC | Высокая, но безвредная | Исправляются один раз; с GitHub Actions — без вашего участия |
| Размытый/сдвинутый остров на 125–200 % | Высокая без манифеста | Манифест PerMonitorV2 сразу |
| Разбиение файла на модули внесёт ошибки | Средняя | Сначала только перенос в файлы без изменений логики; сравнение поведения со старой версией |
