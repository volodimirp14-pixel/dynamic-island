# CHANGELOG

Формат: [версия] — дата — что изменилось.

## [standalone 0.8.0-alpha] — 2026-11-24
Оптимизация и безопасность модуля Bluetooth-значка (по просьбе пользователя). Поведение для пользователя то же.
### Безопасность (устранённые риски падения и зависания)
- **Обращение к освобождённой памяти при выходе.** Обработчики событий Bluetooth и вспомогательный поток «ждём, пока наушники станут звуковым устройством» ссылались на локальные переменные потока Bluetooth. Если событие приходило во время выключения острова, они могли обратиться к уже уничтоженным данным. Теперь общее состояние (`BluetoothRegistry`, `Bt()`) живёт до конца процесса, а обработчики не захватывают локальные переменные.
- **Вечное ожидание.** Все обращения к Bluetooth через WinRT (`FromIdAsync`, `FromBluetoothAddressAsync`, GATT) теперь с тайм-аутом (2–3 с, `AwaitOr`). Раньше «застрявшее» устройство могло навсегда заморозить поток Bluetooth.
- Перенос срока обновления значка — атомарно (`RequestBadgeUpdate`, compare-exchange): события из разных потоков не затирают друг друга.
- Кэш заряда очищается от отключённых устройств и не растёт.
### Оптимизация
- Заряд каждого устройства читается **не чаще раза в минуту** (кэш `g_badgeBattery`). Раньше, пока подключены наушники, каждые 5 с заново опрашивались все устройства: DualSense через HID, остальные через перебор узлов Windows и GATT. Теперь каждые 5 с только дешёвая проверка «есть ли звуковое устройство», а DualSense читается один раз в минуту для всех геймпадов сразу.
- Список звуковых устройств Windows читается один раз на обновление, а не отдельно для каждого устройства.
- Служба батареи BLE ищется из кэша Windows (без радиообмена); свежим читается только сам уровень заряда.
- Приём сигналов AirPods: Windows сама отбрасывает все рекламные пакеты, кроме Apple (фильтр по 0x004C), и игнорируются слабые сигналы (< −80 дБм, соседние комнаты).
- Проверка подключения и обновление значка объединены: при обновлении значка проверка не выполняется второй раз.
### Проверено
- Сборка в CI без ошибок и новых предупреждений. На устройствах пользователя не проверено.

## [standalone 0.7.7-alpha] — 2026-11-24
### Добавлено
- **Заряд AirPods / Beats.** Windows его не знает, но наушники Apple сами постоянно рассылают заряд в рекламных пакетах Bluetooth LE (сообщение «proximity pairing», то же, что видит iPhone при открытии кейса). Пока AirPods подключены, остров пассивно слушает эти пакеты (без сопряжения и без отправки чего-либо) и берёт самый сильный сигнал — то есть ближайшие наушники. Показывается заряд наушника с меньшим уровнем (шаг 10 %), зелёная батарейка — если наушник заряжается. Прослушивание выключается, когда AirPods отключены.
### Ограничение
- Если рядом чужие AirPods с более сильным сигналом, могут показаться их проценты (зашифрованную часть пакета, по которой можно узнать «свои», без ключей iPhone не прочитать).

## [standalone 0.7.6-alpha] — 2026-11-24
### Исправлено (по логу пользователя)
- AirPods называются в Windows **«… - Find My» и в обычном (звуковом) подключении** — фильтр по названию из 0.7.4 отбрасывал и настоящие наушники. Фильтр по названию убран.
- Настоящая причина «наушники подключены, хотя лежат в кейсе»: AirPods держат связь Bluetooth и в кейсе. Теперь наушники и колонки считаются подключёнными, **только пока Windows может выводить через них звук** (есть активное звуковое устройство с их именем — как в списке устройств вывода Windows). Пока наушники показаны или подключены без звука, это проверяется каждые 5 с, поэтому значок появляется и пропадает быстро.
- Всплывашка «Bluetooth — Подключено» для наушников появляется, когда они стали звуковым устройством (ожидание до 8 с в отдельном потоке, не задерживая другие события).
### Ограничение
- AirPods не сообщают Windows свой заряд — у них будет значок без процентов.

## [standalone 0.7.1-alpha] — 2026-11-24
### Исправлено (по логу пользователя)
- **Геймпад «висел» подключённым после выключения.** Наблюдатель Bluetooth не получал смену «подключён/отключён» (не был запрошен признак `System.Devices.Aep.IsConnected`). Теперь он запрашивается и обрабатывается (`Updated`), плюс каждые 10 с остров сам спрашивает Windows, подключено ли устройство. Значок пропадает в течение нескольких секунд после отключения.
- **У DualSense не было процентов.** Переключение в полный отчёт срабатывало (`[Pad] requested the full report…`), но затем читался один из старых коротких отчётов из очереди Windows. Теперь отчёты читаются до 1 с, пока не придёт полный; в лог пишется заряд или какие отчёты пришли.
- Для DualSense больше не запускаются 6 повторных попыток прочитать заряд через Windows при подключении (они всегда безуспешны) — меньше мусора в логе. Убраны подробные строки `BT battery: …` для каждого узла устройства.
### Изменено
- В значке Bluetooth **только иконка и заряд**, без названия устройства.

## [standalone 0.7.0-alpha] — 2026-11-24
### Почему заряд Bluetooth «не работал»
- Заряд читался **только в момент подключения** и показывался 4 секунды во всплывашке «подключено». Устройства, подключённые до запуска острова, не проверялись вовсе, а постоянного места для заряда не было.
- Геймпады PlayStation (DualSense, DualShock 4) Windows вообще не сообщает заряд — его нет ни в свойствах устройства, ни в стандартной службе батареи.
### Добавлено
- **Значок Bluetooth-устройства с зарядом** слева сверху на вкладке часов (развёрнутый остров) и на вкладке плеера (справа от обложки): иконка по типу (геймпад, наушники, колонка, мышь, клавиатура, прочее), на вкладке часов при одном устройстве — его название, батарейка с заполнением и проценты. Красная при 20 % и ниже, зелёная при зарядке. Несколько устройств — компактные значки; сначала с известным зарядом, затем геймпады, наушники…
- Список подключённых устройств ведётся постоянно (в том числе подключённых до запуска); заряд перечитывается раз в минуту и через 4 с после подключения/сразу после отключения.
- **DualSense / DualSense Edge / DualShock 4**: заряд и зарядка читаются из HID-отчёта геймпада (как в Steam/SDL). По Bluetooth геймпад один раз переводится в расширенный режим запросом калибровки — можно выключить (`Modules.SonyPadBattery`).
- Новый тип устройства «геймпад»: по названию (controller, gamepad, DualSense, DualShock, Xbox, Joy-Con, 8BitDo, «Wireless Controller») и по классу Bluetooth.
- Настройки `Modules.BluetoothDashboard`, `Modules.SonyPadBattery`; в Launcher — подраздел «Модули → Bluetooth-устройства».
- Телефоны в значок не попадают (подключённый для звонков телефон — не аксессуар).
### Ограничения
- Для остальных устройств заряд показывается, если его знает сама Windows (как в «Параметры → Bluetooth и устройства») или устройство отдаёт его по стандартной службе батареи BLE. Иначе — только значок без процентов.
- Не проверено на реальном оборудовании (нет Windows и устройств в среде разработки).

### Удалено (по просьбе пользователя)

  - Настройки → кнопка-шестерёнка на острове; Выйти → кнопка выключения на острове;
  - «Не беспокоить» → тумблер на острове и Ctrl+Alt+N; Скрыть/показать → горячая клавиша (Ctrl+Alt+D по умолчанию);
  - Тема, форма, прозрачность, «раскрывать при наведении» → Launcher (раньше меню могло перекрывать эти настройки; эти перекрытия убраны, теперь решают только настройки);
  - Таймер фокусировки → кнопки на Главной Launcher (новая команда острову `timer`);
  - Закрепить развёрнутым → двойной щелчок по острову (как и было);
  - Источник музыки → список «+N» в плеере (как и было);

- **Кнопка выключения** слева от шестерёнки. Нажатие — остров сжимается той же анимацией, что и при «Не беспокоить», затем программа корректно завершается (баннеры Telegram/Discord возвращаются). Страховка: выход через 2,5 с, даже если анимация не отчиталась.
- Шестерёнка и кнопка выключения — **в кругах** (тонкое кольцо и лёгкая заливка), значки 80 % размера.

- `ShowContextMenu` и состояние `PillOpacityOverride`, `ExpandOnHoverOverride`, `W11StyleOverride`, `NotchStyleOverride`, `GameOverlayPinned`, `ColorThemeV2` удалены; тема, форма, прозрачность и раскрытие берутся только из настроек.

## [standalone 0.2.0-alpha] — 2026-11-24
Этап 2b: **остров работает без Windhawk.** Функции те же, что в Windhawk-версии 1.4.0-custom.20 (ничего не добавлено и не возвращено из удалённого).
### Добавлено
- `src/island/IslandCore.cpp` — код острова из мода. Перенос сделан скриптом `tools/port_core.py` (можно перепроверить): все вызовы Windhawk заменены, логика не менялась.
  - `Wh_GetIntSetting`/`Wh_GetStringSetting` → `di::settings` (файл `%APPDATA%\DynamicIsland\settings.json`).
  - `Wh_Get/SetIntValue`, `Wh_Get/SetStringValue` → `di::state` (`state.json`: «Не беспокоить», скрыт/закреплён, прозрачность и форма из меню, бэкап баннеров Telegram/Discord).
  - `Wh_Log` → `DI_LOG` (`%LOCALAPPDATA%\DynamicIsland\logs\island.log`).
  - Точка входа Windhawk (tool-mod) → `main.cpp` + `di::island::Start/Stop/ApplySettings/Show/SetProgress`.
  - Класс окна `DynamicIsland.Island`; пункт меню «Open Windhawk settings» → «Настройки (settings.json)» (открывает файл в Блокноте; на этапе 3 — Launcher); новый пункт «Выйти из Dynamic Island».
  - `GameDetector`: вместо окон Windhawk «не игрой» считается будущий `DynamicIslandLauncher.exe`.
  - `ProgressPercent` (кольцо прогресса) сохранено: `DynamicIsland.exe --progress 40` (или команда от Launcher), `-1` скрывает.
- `src/shared/settings_schema.json` — описание всех 109 настроек (тип, значение по умолчанию, варианты, названия), сделано из YAML мода (`tools/yaml_to_schema.py`). Встроено в exe.
- Настройки: при отсутствии файла создаётся со значениями по умолчанию; испорченный файл сохраняется как `settings.broken-<время>.json`; неверные значения заменяются значениями по умолчанию; перед перезаписью — `settings.json.bak`; запись атомарная.
- Изменения `settings.json` применяются сразу после сохранения (слежение за папкой).
